## 1. Цели и метрики

| Цель | Метрика | Цель через 90 дней после запуска |
|---|---|---|
| Клиенту не нужно звонить | доля записей онлайн | ≥ 70% |
| Владелец не тратит вечер на запись | время владельца на запись/подтверждения | ≤ 10 мин/день |
| Нет пустых окон | заполняемость слотов | ≥ 85% |
| Нет прогулов | no-show | ≤ 5% |
| Клиенты возвращаются | повторный визит за 90 дней | ≥ 35% |
| Сайт находится | органический трафик из Яндекса | ×2 к текущему |
| Сайт быстрый | LCP p75 мобильный | ≤ 2,5 с |
| Воронка записи | старт записи → оплаченная запись | ≥ 45% |

## 2. Границы (scope)

**Входит в MVP (релиз 1):** публичный сайт, каталог услуг и мероприятий, онлайн-запись с предоплатой, лист ожидания, правила открытия записи, напоминания (MAX/SMS/email), самообслуживание (перенос/отмена), админка (услуги, расписание, мероприятия, акции, гости), согласия и cookies, SEO-разметка, аналитика Яндекс Метрики (после согласия).

**Релиз 2:** магазин с click-to-buy (перенос каталога с Tilda), подарочные сертификаты, бонусная система и рефералка, бот-ассистент владельца с командами, дашборд денег, кросс-постинг VK/MAX.

**Релиз 3:** LLM-черновики текстов (YandexGPT/GigaChat), A/B-тесты, мобильное приложение (ветка `mobile` шаблона) — только если метрики покажут спрос.

**Не входит:** собственная CRM-телефония, маркетплейсы (Ozon/WB), многоязычность.

## 6. Мастер записи [A3]

**Шаг 1 — Что:** локация (если > 1) → категория → услуга. Пропускается, если зашли со страницы услуги.
**Шаг 2 — Когда:** сверху «ближайшие окна» (до 8), ниже календарь недели. Недоступные дни серые, с подписью причины («запись откроется 16.08 в 22:00», «выходной»). Кнопка «Нет подходящего? Встать в лист ожидания».
**Шаг 3 — Кто вы:** имя, телефон (маска +7), комментарий (необязательно). Чекбокс согласия на обработку ПДн (обязательный, **не** предустановлен, ссылка на текст согласия). Отдельный чекбокс «Хочу получать новости и акции» (необязательный). Выбор канала: MAX / SMS / email / VK / Telegram.
**Шаг 4 — Оплата:** сумма предоплаты, политика отмены коротко (1 строка + ссылка), СБП/карта. Hold слота с таймером 15:00 на экране.
**Успех:** «Вы записаны» + добавить в календарь (.ics) + маршрут + что взять с собой + ссылка управления записью. Сообщение в выбранный канал.

Требования: прогресс «Шаг N из 4»; состояние в URL (можно вернуться назад); работает без JS-фреймворка до шага 2 (остров Astro гидратируется при видимости); ошибки инлайн; в поле телефона `autocomplete="tel"`, `inputmode="tel"`; клиент, уже подтверждённый на этом устройстве, видит шаг 3 предзаполненным.

Инварианты:
- Все деньги в копейках (`Int`). Все времена в UTC в БД, отображение в `Location.timezone`.
- Бронирование слота делается в одной транзакции с `SELECT … FOR UPDATE` по ресурсам, либо через exclusion constraint Postgres (`tstzrange` + `gist`) на `(resourceId, during)` для статусов HOLD/PENDING_PAYMENT/CONFIRMED. **Двойная запись невозможна на уровне БД.**
- Групповые услуги/мероприятия: `SUM(seats) ≤ capacity` проверяется в транзакции.
- Удаление клиента = анонимизация (имя → «Удалено», телефон → хэш), финансовые записи сохраняются (налоговые сроки).

## 8. Алгоритмы автоматизации

### 8.1 Расчёт слотов
`slots(service, location, dateRange)` = рабочие часы ресурсов − TimeOff − занятые брони (с буферами) − ещё не открытое по ReleaseRule; шаг сетки = настройка (по умолчанию 30 мин); длительность = `durationMin + buffers`. Результат кэшируется на 60 с и инвалидируется при любом изменении брони.

### 8.2 Правила открытия записи [B1, B2]
- `FIXED_MONTHLY`: «запись на следующий месяц открывается {dayOfMonth} в {time}». До этого момента слоты видны серыми с таймером «откроется через…».
- `DAILY_ROLLING`: «каждый день в 18:00 открывается день D+N» (замена ручной выкладки в 18:00).
- `WINDOW_DAYS`: «всегда открыто на N дней вперёд».
- Ранний доступ: сегмент (лист ожидания / бонусная карта уровня X / был ≥ 2 раз) получает ссылку за `hoursBefore` до общего открытия; слоты для них открыты по персональному токену.
- В момент открытия: сообщение «Запись открыта» подписанным на это событие (только с рекламным согласием или как сервисное, если человек сам нажал «сообщить, когда откроется»).

### 8.3 Hold и оплата [B3, B4]
Шаг 3 создаёт `Booking(status=HOLD, holdExpiresAt=now+15m)` → платёж → webhook провайдера → `CONFIRMED`. Джоба каждые 60 с снимает просроченные HOLD (→ `CANCELLED`, reason=hold_expired) и триггерит лист ожидания. Webhook'и идемпотентны (ключ `providerId`), подпись проверяется.

### 8.4 Лист ожидания [B5]
Событие «освободился слот/место» → найти `WaitlistEntry` в статусе WAITING, чьё окно покрывает слот, по `position` → создать HOLD на 30 мин под этого клиента → сообщение «Освободилось {время}. Забрать?» с кнопкой → истёк без ответа → `EXPIRED`, следующий. Отдельно: владелец видит очередь и может вручную предложить.

### 8.5 Напоминания и подтверждения [B7]
T-24ч: «Ждём вас завтра в {время}. [Подтверждаю] [Перенести] [Отменить]». T-3ч: короткое напоминание + маршрут. Нет подтверждения к T-3ч → пометка в разделе «Сегодня» у владельца. Для мероприятий: T-48ч и T-3ч. Все времена отправки — в окне 9:00–21:00 местного времени (кроме записи «на сегодня»).

### 8.6 Перенос / замена / отмена [B6]
По `manageToken` (ссылка в каждом сообщении) без логина. Перенос: доступно до `policy.rescheduleUntilHours`. Замена услуги в рамках одного `PriceGroup` — без доплаты [правило «равная длительность = равная цена»]. Отмена: до `policy.freeCancelHours` — автоматический возврат предоплаты; позже — по политике (возврат за вычетом фактически понесённых расходов; текст согласовать с юристом).

### 8.7 Каналы сообщений [C1]
`notify(clientId, templateKey, vars)` → берёт предпочтения клиента → пытается канал 1 → при ошибке/недоставке за X мин → следующий. SMS — только для `critical` шаблонов (подтверждение, перенос, отмена, лист ожидания), если мессенджер не сработал. Маркетинговые шаблоны отправляются **только** при `Consent(MARKETING)=granted`, с ссылкой отписки.

### 8.8 После визита [C5, D5]
Мастер/админ отмечает «пришёл» (или автоматически через 30 мин после окончания, если нет отметки no-show) → +баллы → через 2 ч «спасибо» от владельца + ссылка на отзыв (Яндекс Карты) → за опубликованный отзыв на сайте +баллы (после модерации).

## 9. Админка (webapp, PWA) [D1–D8]

Разделы нижнего таб-бара (мобайл): **Сегодня · Расписание · Каталог · Афиша и акции · Гости**; «Ещё» → Отчёты, Настройки, Шаблоны сообщений, Правовые документы, Команда, Экспорт.

- **Сегодня:** список визитов, статусы подтверждения (зелёный/жёлтый/красный), кнопки «Пришёл / Не пришёл / Позвонить / Написать», свободные окна сегодня с кнопкой «Отправить листу ожидания».
- **Расписание:** день/неделя, drag-n-drop переноса (десктоп), long-press (мобайл); «Закрыть день», «Отпуск» (диапазон → все записанные получают сообщение с ссылкой на перенос).
- **Каталог (услуги):** список с переключателем вкл/выкл; карточка = Название, Категория, Длительность (чипы 30/60/90/120), Цена по локациям, Фото (drag-drop, автосжатие), Описание (простой редактор), «Только для новых». Кнопки «Дублировать», «Изменить цену с даты».
- **Афиша и акции:** мастер «Новое мероприятие» из 1 экрана; «Повторять еженедельно»; акции с датами и баннером; превью, как это будет на сайте.
- **Гости:** поиск по имени/телефону, история визитов, баллы, согласия (видно, на что согласен), кнопка «Удалить данные по запросу» (с подтверждением и записью в журнал).
- **Настройки:** правила открытия записи (понятным языком: «Открывать запись на следующий месяц [16] числа в [22:00]»), политика отмены, предоплата, часы работы, каналы, реквизиты.
- **Шаблоны сообщений:** список событий → текст с переменными → «Отправить себе тест».
- **Отчёты [D8]:** выручка, заполняемость, no-show, источники, воронка, топ-услуги, повторные визиты.

UX-правила админки: любое действие ≤ 3 тапа; никакого HTML/вёрстки; автосохранение черновиков; отмена последнего действия (undo 10 с); все формы проверяются Zod с понятными русскими ошибками.

## 10. Бот-ассистент владельца (релиз 2) [C3, C4]

Каналы: MAX (основной), Telegram (опционально). Доступ только для `StaffUser` с подтверждённым номером.

Команды (кнопками и текстом):
- «Сегодня» / «Завтра» — расписание.
- «Закрыть {дата}» / «Отпуск {с}–{по}» — черновик → «Подтвердить?» → выполнено + отчёт, кому ушли сообщения.
- «Акция …» — разбор (релиз 3: LLM без ПДн; релиз 2: пошаговый диалог) → черновик → подтверждение → публикация.
- «Мастер-класс {дата} {время} {мест} {цена} {название}» → черновик события → подтверждение → страница + кросс-пост.
- Вечерний дайджест 21:00 [C4] и мгновенные уведомления о новой записи/отмене (настраиваемо).

Правило: бот **никогда** не публикует и не рассылает без явного подтверждения владельца.

## 11. SEO и AI-поиск [F1–F6]
- SSG-страницы Astro, `<title>` ≤ 60 симв. и description ≤ 160 из полей SEO (с автогенерацией по шаблону, если пусто).
- JSON-LD: `LocalBusiness` (адрес, geo, openingHours, telephone, priceRange, sameAs: Яндекс Карты/2ГИС/VK), `Service`/`Offer`, `Event` (с `offers.availability` из live-данных при билде + ISR/пересборка по вебхуку), `Product`, `FAQPage`, `BreadcrumbList`, `AggregateRating` только из реальных отзывов.
- Пересборка статических страниц по вебхуку из админки (изменили услугу → пересобралась её страница и sitemap) ≤ 2 мин.
- `llms.txt` с кратким описанием бизнеса, услуг, цен, адреса, ссылок.
- Редиректы 301 со старых URL Tilda (`/politika`, `/oferta`, `/members/login`, `#rec…` якоря неважны).
- Яндекс Вебмастер + Яндекс Бизнес (кнопка «Записаться» → `/w/…?utm_source=yandex_maps`).

## 12. Нефункциональные требования
- **Производительность:** LCP ≤ 2,5 с (p75, 4G), INP ≤ 200 мс, CLS ≤ 0,1; JS на главной ≤ 70 КБ gzip; изображения AVIF/WebP с `srcset`; шрифты самохостинг, `font-display: swap`, subset кириллица+латиница.
- **Доступность:** WCAG 2.2 AA; все интерактивные цели ≥ 44×44; фокус видим; формы с `<label>`; `prefers-reduced-motion` отключает видео/анимации.
- **Надёжность:** бэкапы Postgres ежедневно (PITR 7 дней), тест восстановления раз в месяц; мониторинг (Yandex Monitoring + алерт владельцу/разработчику); SLA записи 99,5%.
- **Безопасность:** OWASP ASVS L1; rate-limit на отправку кода и создание броней; CSRF для админки; секреты в Lockbox; 2FA по коду для ролей владелец/админ; журнал доступа к ПДн.
- **Тесты:** unit (расчёт слотов, правила открытия, лист ожидания, политика отмены — 100% веток), интеграционные (транзакции броней, гонка 50 параллельных броней на 1 слот → ровно 1 успех), e2e Playwright (мастер записи на 360×800 и 1440×900, оплата в тестовом режиме, перенос по ссылке), Lighthouse CI (perf ≥ 90, a11y ≥ 95, SEO = 100).
- **Экспорт/переносимость:** CSV/JSON всех сущностей из админки.

## 13. Миграция с Tilda
1. Выгрузить каталог товаров Tilda (CSV) → импорт в `Product` (релиз 2).
2. Скачать изображения с `static.tildacdn.com` → Object Storage, конвертация.
3. Перенести тексты «О нас», реквизиты, правовые документы (переписать под новые требования).
4. 301-редиректы; сохранить счётчик Метрики 104806559 (но запуск только после согласия).
5. Переключение DNS в низкий сезон, TTL заранее 300 с.

## 14. Критерии приёмки MVP (чек-лист)
- [ ] С мобильного за ≤ 60 с можно записаться и оплатить (замер на 5 людях не из команды).
- [ ] Телефон виден в шапке на всех страницах и звонит по тапу.
- [ ] Нет ни одного всплывающего модального окна, кроме платёжной формы провайдера.
- [ ] 50 параллельных броней одного слота → 1 подтверждена, 49 получают «слот только что заняли, вот ближайшие».
- [ ] Правило «открыть запись на месяц 16-го в 22:00» срабатывает без участия человека; ранний доступ работает.
- [ ] Отмена записи → через ≤ 1 мин первый из листа ожидания получил предложение.
- [ ] Владелец меняет цену услуги с телефона за ≤ 3 тапа; страница услуги на сайте обновилась ≤ 2 мин.
- [ ] Согласия: отдельные тексты, не предустановлены, версия документа сохраняется, отзыв согласия работает.
- [ ] Метрика не загружается до согласия на аналитические cookies.
- [ ] Никаких запросов к иностранным доменам при загрузке страниц (проверка в DevTools/Playwright).
- [ ] Lighthouse мобайл: Perf ≥ 90, A11y ≥ 95, Best Practices ≥ 95, SEO 100.
- [ ] Rich Results / валидатор микроразметки Яндекса: без ошибок для LocalBusiness, Event, Service, FAQPage.
- [ ] Резервная копия восстановлена на стенде.
