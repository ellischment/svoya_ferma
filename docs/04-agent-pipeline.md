# 04. Агентный конвейер: как сделать проект без ручной передачи между этапами

## 1. Ответ на вопрос «лучше агентами?»
Да, но **не толпой агентов на всё подряд**. Самое дорогое в агентной разработке — контекст и токены умной модели (см. опыт автора vibe: «$200 улетают за два дня»). Поэтому:

- **Оркестратор** (главная сессия Claude Code, сильная модель) только планирует, принимает решения и проверяет гейты. Сам код почти не читает.
- **Scout** (дешёвая модель, только чтение) делает разведку перед каждой задачей и приносит карту из 3–7 файлов со ссылками на строки. Это идея `code-scout-skill`, у нас она оформлена как саб-агент `.claude/agents/scout.md`.
- **Builder** (средняя модель) пишет код по одной задаче из `CHECKLIST.md`.
- **Reviewer / QA / Legal / SEO** (средняя модель) — независимые проверяющие со своим чек-листом. Код они не пишут, возвращают только находки.
- Цикл крутится сам через `/loop` + `CHECKLIST.md`: взять задачу → scout → build → test → review → исправить → закоммитить → следующая задача. Человек нужен только на **гейтах** (помечены 🚦).

```
                ┌───────────── CHECKLIST.md (бэклог с ID задач) ─────────────┐
                ▼                                                            │
  Оркестратор ──► scout (haiku/sonnet, read-only) ──► карта файлов           │
       │                                                                     │
       ├──► builder (sonnet) ──► код + тесты ──► `bun test`, lint, typecheck │
       │                                           │ красное → builder снова │
       ├──► reviewer (sonnet) ──► находки ──► builder исправляет ────────────┤
       ├──► qa-e2e / legal-auditor / seo-auditor (на гейтах релиза)          │
       └──► commit + отметка [x] в CHECKLIST.md ─────────────────────────────┘
```

## 4. Экономия токенов (правила для оркестратора)
1. Никогда не читать файлы целиком, если scout может принести ссылки на строки.
2. Одна задача из CHECKLIST = один саб-агент builder = одна свежая сессия контекста.
3. Проверяющие получают **diff**, а не репозиторий.
4. Максимум 3 круга «review → fix» на задачу. Если не сошлось — задача помечается `[!]` с описанием блокера и оркестратор идёт дальше.
5. Длинные артефакты (логи тестов) не тащить в контекст: `tail -50`.

## 5. Как запустить
1. Создать пустую папку/репозиторий (этот репозиторий уже подготовлен: `CLAUDE.md`, `CHECKLIST.md`, `.claude/agents/`, `docs/`).
2. В Claude Code: вставить содержимое `prompts/00-master-orchestrator.md`.
3. После бутстрапа: `/loop` с промптом из раздела «Цикл» в `prompts/00-master-orchestrator.md`, и дальше цикл идёт сам, пока не упрётся в 🚦.
4. На гейтах вы отвечаете в чат (или в комментариях к PR), и цикл продолжается.
