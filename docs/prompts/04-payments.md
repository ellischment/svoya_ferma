# Промпт 04 — Платежи и чеки 54-ФЗ (builder)

```
Задача: backend/src/payments — интерфейс PaymentProvider { createPayment, getStatus, refund, verifyWebhook }
и две реализации: yookassa (API v3) и tbank (Эквайринг API v2). Выбор через env PAYMENT_PROVIDER.
Плюс `fake` для dev/e2e (страница-имитатор оплаты с кнопками «Успех/Ошибка»).

Требования:
- Суммы в копейках; валюта RUB; СБП и карты.
- Чек 54-ФЗ в каждом платеже: позиция = услуга/мероприятие/товар, payment_subject = service|commodity,
  payment_mode = full_prepayment (при записи заранее) / full_payment; НДС из настроек (TODO(owner): система
  налогообложения); контакт покупателя — телефон или email клиента. Чек возврата при refund.
- Webhook: проверка подписи/IP-allowlist по документации провайдера, идемпотентность по providerId,
  перевод Booking HOLD→CONFIRMED, запись Payment. Поздний webhook после истечения hold: если слот ещё свободен —
  подтвердить; если занят — автоматический refund + сообщение клиенту с альтернативами.
- Return URL → website /zapis/uspeh?b=... (страница опрашивает статус, не доверяет query).
- Промокоды/акции применяются на сервере при расчёте суммы (никогда не доверять клиенту).
- Секреты только из env/Lockbox.
Тесты: unit для расчёта суммы (акция %, фикс, депозит %, минимальная сумма), контрактные тесты на payload
провайдеров (фикстуры из документации), e2e на fake-провайдере.
🚦 Попроси владельца провести тестовый платёж в тестовом магазине провайдера и прислать скрин чека.
```
