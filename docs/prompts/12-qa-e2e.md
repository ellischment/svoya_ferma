# Промпт 12 — QA: e2e, нагрузка, доступность (qa-e2e)

```
Цель: доказать критерии приёмки docs/01-TZ.md §14. Ничего не чинить самому — только тесты и отчёт с находками.

Playwright (chromium из /opt/pw-browsers или системный), проекты: mobile 390×844 (touch), desktop 1440×900.
Сценарии:
1. Новый гость: главная → «Ближайшие окна» → чип → Кто вы → согласие → fake-оплата → успех → сообщение в dev-outbox.
   Замер времени от первого клика до успеха (цель ≤ 60 с «человеческого» темпа — считаем шаги и поля).
2. Слот забрали во время заполнения → понятное сообщение + альтернативы.
3. Запись ещё не открыта → «сообщить, когда откроется» → промотка времени (фейковые часы) → сообщение пришло.
4. Отмена записи → первый из листа ожидания получает предложение ≤ 1 мин (фейковые часы) → принимает → оплачивает.
5. Перенос и замена услуги по ссылке из сообщения, без логина.
6. Владелец (админка, mobile): меняет цену за ≤ 3 тапа; создаёт мастер-класс; ставит отпуск → клиенты уведомлены.
7. Согласия: без чекбокса нельзя; Метрика не грузится до cookie-согласия; отзыв рекламного согласия работает.
8. Сетевой аудит: список всех внешних доменов на всех страницах → сравнение с allowlist.
9. a11y: axe-core на всех шаблонах; навигация только с клавиатуры по мастеру записи.
10. Нагрузка (k6 или autocannon): 50 параллельных hold на 1 слот → 1 успех; 200 RPS на /api/slots p95 < 300 мс.
11. Визуальная регрессия: скриншоты шаблонов, сравнение с baseline.
Отчёт: docs/qa/report-<дата>.md — таблица критериев приёмки PASS/FAIL со ссылками на артефакты; FAIL → новые задачи
в CHECKLIST.md с тегом [bug].
```
